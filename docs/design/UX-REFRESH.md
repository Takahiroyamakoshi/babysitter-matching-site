## 根拠・範囲
親が今回の実ブラウザーで公開画面を観測（ログイン・実予約なし）。
- [キッズライン](https://kidsline.me/sitter): 「ベビーシッターを検索」。1280pxで実測211pxの条件欄と画像上約680pxの主領域。日時と年齢・人数・時給・資格を見出しで区分。
- [KIDSNAシッター](https://sitter.kidsna.com/pref/all): 「ベビーシッターを探す」。結果3列、約630pxの絞込み画面で地域・子どもの年齢・日時・対応条件を区分。
- 親の実測監査: [UX-AUDIT.md](UX-AUDIT.md)、証拠は evidence/ux-refresh/。02/03のKIDSNA、04/05のKidsline、06の現検索、08の相談、09の見積りを参照。本担当は監査資料を読み、画像の独立確認はしていない。2時間検索が200/0件となる証拠はinvalid-time-api.json。07-before-invalid-time.pngは入力が戻った不採用画像であり根拠にしない。
採用は明確な表題、依頼条件と希望条件の区分、結果の視覚的序列。競合の幅やモーダルの複製は不要。既存React/TypeScript・Node APIを維持、追加ライブラリ不要。PCは検索条件/結果を区分し説明だけのカードへ半幅を割かず、相談は会話およそ2/3・編集欄1/3を目安、モバイルは1列。全体サイドバー・グローバルナビ再設計、画像生成、実認証・決済・本番公開は対象外。

## 要件と画面判断
| ID | 実装する振る舞い |
|---|---|
| UX01 | 「お子さま・依頼日時」に開始/終了・子どもごとの生年月日。「シッターの希望条件」に地域・資格・時給上限を配置して見出しで分ける。 |
| UX02 | 最低3時間・15分刻みを検索操作付近に示す。3時間未満は「通常保育は最低3時間です」と理由を示して検索不可。APIも候補の絞込み前に共通日時/対象児検査を行い422。正常0件・入力不正・通信失敗を区別し、旧結果を新条件の結果として残さない。 |
| UX03 | 人数は1〜3人のみ、3人の条件付き説明を維持、4人選択肢を除く。人数増加時にDOBを複製して全員分を入力済みにしない。APIの4人拒否を維持する。 |
| UX04 | ブランド名とは別に画面ごとの主見出しを動的に表示。保護者の検索は「シッターを探す」、相談は「〇〇さんに相談」、概算は「保育料の概算を確認」。シッター利用時は「シッターの掲載を見る」等の役割と作業に合う表題にし、利用者向け表示へ内部技術用語を持ち込まない。 |
| UX05 | カードは地域・対応年齢・資格・時給・人数のラベル/値。「同時に預かれる子どもの人数：最大2人」等と表示。月数を「6か月〜10歳」等へ変換する。ただしfixture上限120か月はサービス上限ではないため「このサービスの対象：小学3年生の年度末まで」を併記し10歳まで必ず受付可能と誤認させない。人数も無条件受付の保証にしない。 |
| UX06 | 未選択の「相談」「見積り・依頼」はDOMから非表示。選択後は相手名を示す。全体サイドバー・固定リンク構成は後続。 |
| UX07 | 相談内で日時/子どもを編集でき、チャットと選択相手を維持して再見積りできる。変更後は旧見積りと同意を失効させて再計算・再確認する。 |
| UX08 | 保護者には基本保育料、夜間加算（21時〜8時の該当時間のみ20%）、保育料合計、交通費状態、総額を表示。夜間分を合計に二重加算しない。運営手数料とシッター手取りは保護者に表示せず、シッターの依頼確認で区分表示する。 |
| UX09 | 交通費未確定なら「保育料の概算（交通費を除く）」、交通費「相談して確定」、総支払額「未確定」。fixture交通費を確定額として流用しない。正式依頼前に相談した交通費提案額を明示入力し、保護者は当該額と全総額を確認して送信。受信シッターも交通費を含む条件を明示確認して承認。 |

横断条件（UX02/07/09・既存L07/L08）: 条件・相手・交通費の変更と再見積りで旧見積り/同意を無効化。通信/保存失敗で入力を保持し、同一operationIdの再試行は二重作成しない。375px/1280pxでラベル・フォーカス・主要操作が読み取れ横溢れなし。fieldset/legendで区分し、エラーをaria-invalid/aria-describedbyと要約へのフォーカスで伝える。

## 最小API・状態変更
- 検索: listSittersのfilter内で例外を握り潰す前にparseSlot相当の共通検査。不正条件（4人含む）は明示エラー、個別シッターの年齢/人数不適合は候補除外。
- 見積り入力に任意のtransportAmount（非負整数・円）を追加。未指定はquote.transport/guardianTotalをnull、交通費状態pendingで保育料のみ計算。0円は明示入力時のみ有効。指定済みは当該提案額＋保育料で全総額をサーバー算出。fixture.transportを採用しない。既存の保育料・15%手数料計算は維持。
- 新規正式依頼はtransportAmountと保護者の交通費確認（acceptTransport等）必須、未確定/不正/未確認は422。保護者が相談内容を転記した「交通費提案」でありサーバーは合意成立を推定しない。シッター承認も当該交通費確認（acknowledgeTransport等）必須として相互確認を完成する。往復の合理的経路の実費を相談する説明を置き、実経路・番地の新規取得はしない。
- 新依頼に交通費提案/保護者確認、全料金、日時・全対象児・規則版を保存、承認の交通費確認も記録。予約へ同じスナップショットを引き継ぐ。承認時の適合再検査で現在fixture交通費へ置換しない。
- schema1の保存済み依頼・予約・operationsをリセット/書換えしない。旧数値交通費は保存済み見積りとして表示。新規ルールは追加フィールド/規則版で区別する。旧operationId同内容再送は保存結果を優先し、新必須入力で過去成功分を拒否しない。異内容の同一IDは従来どおり拒否。
- quote型は未確定と金額ありを区別しnullを0にしない。quoteKey/fingerprintに各児童DOB・日時・相手・交通費を含める。非同期応答は最新actor/相手/条件と一致する場合だけ採用し、古い見積りを別条件へ反映しない。
