## 目的・範囲・承認
登録 → 検索 → チャット → 見積り付き正式依頼 → シッター承認を合成データで確認する。通常保育の単発予約を最初の動作可能な増分とし、製品全体の MVP 完了とは呼ばない。
docs/PROJECT.md 記載の2026-10-17「お願い」がこの範囲の実行依頼と初期計画確認の根拠。通常設計は委任済み。独立レビューは親が別担当へ依頼する。
対象は保護者／シッターのデモ登録、プロフィール・合成対象児・空き枠、地域／日時／年齢／人数／料金／資格検索、テキストチャット、通常保育の見積りと依頼・承認・辞退・失効、予約一覧。
後続は本番認証、実個人情報、書類提出・実審査、決済・メール・事故運営・AI、面談・送迎・定期・延長・取消精算・実績・レビュー・お気に入り、PWAオフライン、クラウド配備。製品要件から削除せず、未実装サービスは画面と API で受付禁止とする。

## デモの境界
全画面でローカルデモ・実情報入力禁止を表示。利用者切替は認証・本人確認ではない。身分証、連絡先、番地、医療資料、銀行情報の欄は作らない。自由文にも合成情報だけを入力する。
資格・必要研修・届出・初回保険の全てを合成審査条件として管理し、一つでも未確認なら掲載・受付不可。新規シッターは確認待ち。検索掲載・受付はサーバーで用意した合成審査済み fixture のみ許可し、リクエストの verified フラグや自己申告で昇格できない。「本人確認済み」は表示しない。
複数人条件はサーバー固定の合成適合シナリオとして実装し、法的確認済みと扱わない。未確認条件は拒否。本番有効化には別途制度・保険・権限確認が必要。
UI/API とも loopback 限定。変更系は JSON と専用ヘッダー等を要求し、未知 Host・不許可 Origin を拒否する。デモ actor 切替は本番認証の代替ではないが、API はチャット・依頼の当事者検査を行う。

## 技術と起動
単一 TypeScript / React コードベース。React + Vite の画面、Node HTTP の API、独立したドメイン関数と共有型を採用する。受付判断はサーバーで行う。
親の環境確認では WSL Node はなく Windows bundled Node v24.19 が利用可能。Windows node.exe から npm の JS エントリを直接呼び、無償依存 react/react-dom/vite/typescript/tsx と型定義をプロジェクトへ導入して lockfile を保存する。版は導入時に互換性を検証し確定する。
UNC cwd の npm run / cmd.exe に依存せず、Node 起動スクリプトから各ツールの JS エントリを直接起動する。個人の絶対パスをアプリへ埋め込まない。Vite proxy または一体配信で UI/API を同一 origin にする。
初段で依存導入・最小起動・build・typecheck を検証する。取得失敗時は親へ証拠と最小代替を返す。Cloudflare/D1/R2 の本番適合は今回の達成条件にしない。
Playwright は利用可能だが Chromium キャッシュは未確認。検証担当が既存 Chrome/Edge の実体を確認して利用する。実ブラウザー未確認を合格にしない。

## 保存・競合
単一サーバープロセスでローカル JSON を永続化する。全更新を直列化し、候補状態を同一ディレクトリの一時ファイルへ完全書込み後に置換、成功後だけメモリ更新と成功応答を行う。保存失敗では直前状態を維持する。
登録・メッセージ・依頼・成立予約は画面再読込とサーバー再起動後も残る。初回だけ fixture を作り、既存データを黙って初期化しない。起動時はスキーマ版・形式を検査し破損なら停止する。保存先は Git 対象外。同一保存先の二重起動は拒否する等、単一 writer を保証する。本番分散処理・バックアップ・停電耐性の保証は対象外。
メッセージ・依頼の送信は actor と operation id を保存し、再送を同一結果にする。同一 id で内容が異なる場合は拒否。承認再送も同一成立結果を返し、連打や通信切断後の再試行で二重登録しない。

## 受付・状態規則
- UTC 保存・日本時間表示。時計をサーバーで管理し試験では注入する。
- 通常保育は未来開始、終了 > 開始、最低3時間、開始終了15分刻み。時給は正の整数で10,000円以下。
- 利用日基準で生後6か月以上〜小学3年生年度末。1歳未満は保育士／看護師、幼稚園教諭のみなら研修条件を検査。シッターの対応可能年齢も満たす。
- 1〜3人で、全対象児の年齢・関係・保育内容、シッター人数、地域／例外適用・保険の合成確認条件を全て満たす。未確認組合せは拒否し、クライアントの許可フラグを信用しない。
- 病児・病後児・投薬補助を検索、見積り、依頼作成、承認で拒否。通常保育と称して医療フラグを混ぜても拒否。未実装の変更 API は拒否。チャット本文から医療判断する AI は作らない。
- 検索は適合・空き枠を検査し、依頼作成と承認で現在の適合を再検査する。
- 状態は pending / confirmed / declined / expired。期限 = min(受信時刻+24時間, 開始時刻)。now >= 期限 は失効し承認不可。チャット返信では状態も期限も変わらない。読み書き時に失効反映、利用中画面もポーリング等で更新する。
- 承認者は依頼されたシッターのみ。期限・適合・空き枠検査から保存まで直列化。相談中／承認待ちは枠を占有しない。
- 同一シッターの成立枠の重複・移動余裕を検査。両予約の移動余裕の大きい値を必要間隔とし初期30分。前終了+間隔 <= 次開始で許可。予約時の値を保存し設定変更を遡及しない。

## 見積りと UI
サーバーが時給×人数×時間と、日本時間21時〜8時の部分に限る20%加算を計算。中間は丸めずサービス料合計と15%手数料を各々円未満切捨て。交通費は事前提示するデモ整数額、手数料対象外。保護者総額とシッター向けサービス料／手数料／手取り／実費を区別する。
正式依頼は日時・対象児・種別・単価・割増・交通費・総額・キャンセル条件への同意と規則版をスナップショット保存。取消説明は REQUIREMENTS 第13/29章と整合させる。税区分・実請求は確定せずデモ見積りと明示。成立後のプロフィール料金変更で金額を変えない。
スマホとデスクトップに対応し、ラベル、キーボード、送信中、エラー説明を用意。失敗時は入力を保持し成功扱いにしない。再試行、期限切れ、競合、受付不可を区別する。
