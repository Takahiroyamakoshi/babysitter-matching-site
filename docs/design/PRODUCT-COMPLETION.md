## 1. 完成させる製品と判断基準
シッターの収入・手取りを最大化するため、保護者が条件に合うシッターを選び、直接相談して依頼し、利用後の精算・レビューまで行えるサービスを作る。運営は資格等の確認と例外対応を担う。依頼成立数、継続利用、移動・事務を含む実質時給を改善し、安さ順への誘導を主目的にしない。

初期公開の完成は「通常保育の単発予約が動く」だけではない。保護者・シッター・権限別運営の各利用者が、下記の正常経路と必要な失敗経路を、安全に再開できる証拠が揃った状態とする。全体要件はチェックリストの対応表へ割り当て、未実装・条件待ちを製品から消さない。

| 段階 | 判定対象と必要な証拠 | 権限の境界 |
|---|---|---|
| L: ローカル実証 | 合成データ、ループバック、代替認証・決済・メールで業務と異常時状態を検証。個々のタスクで対象版・環境・限界を記録 | 通常のローカル実装の既存許可は継続する。今ターンは全体計画・棚卸し・独立監査の提示を先行し、全体計画を具体的に確認できる形にする。全タスクで再許可を求める運用にはしない |
| R: 初期公開準備 | 通常保育・定期・面談・徒歩/公共交通の送迎、条件適合する複数人、夜間・延長・変更・取消・実績・精算・レビュー、審査・事故等の運営を含む。採用技術・制度・契約・体制・予算を実証 | 実情報・外部サービス・支出・メール・決済の使用は対象・操作を特定した別許可が必要 |
| P: 初期公開 | Rの全条件を対象版・対象環境で独立確認し、重大な未解決事項がなく、ユーザーが公開対象版・環境を明示承認 | mergeやローカル合格を公開許可にしない |
| C: 条件付き追加提供 | 病児・病後児・投薬補助。安全・制度・保険・保存の調査と判断を終え、該当条件の実装・検証後に有効化 | 初期公開で受付無効のままでもよい。設計・将来受入の範囲から削除しない |
| O: 評価後の追加 | 資格OCR、詳細運営AI、タクシー等の追加範囲。初期AIは自己紹介・FAQ・申請不備案内をRに含む | 詳細運営AIの判断権限・運用範囲を未確定のまま自動執行しない |

## 2. 端から端までの利用と運営
| 利用者 | 成立すべき一連の作業 | 完成判定 |
|---|---|---|
| 未登録の保護者 | 公開検索・プロフィール・空き枠を閲覧し、登録/ログインして子ども・訪問先等を整える | 関東重点でも他地域の登録・利用を一律禁止しない。番地・医療・書類原本を公開しない |
| 保護者 | 検索/お気に入り → 相手と直接画像付き相談 → 見積り・交通費・規則に同意 → 正式依頼 → 承認 → 利用/延長/変更 → 実績確認・異議/支払い → レビュー/通報 → 再利用/退会 | チャットで予約成立しない。未承認料金は請求しない。失敗時は入力と確定済み状態を保持し、修正・再試行可能 |
| シッター | 登録 → 資格/研修/届出/初回保険の提出・確認と外部入金設定 → 掲載 → 時給/対応条件/週次空き枠/日例外/移動余裕 → 相談・依頼承認 → 開始/終了/引渡し → 実績 → 手取り・入金予定 | 自己申告で審査済みに昇格しない。受付・重複・移動条件を承認時にも原子的検査。保険期限後は既合意の通知のみで自動停止しない |
| 審査担当 | 申請/再提出/疑義の確認、根拠・担当・日時・履歴、資格/届出の状態、保険更新と期限通知、共通時給上限 | 身分証を収集せず「本人確認済み」と偽表示しない。待機中の申請を無条件合格にしない |
| 事故/問い合わせ担当 | 予約に紐づく双方の独立報告 → 緊急通知/優先一覧 → 個別メールと必要な相手確認 → 未対応/対応中/完了・事実確認・案内・再発防止 | 報告は報告者本人と権限のある運営だけ閲覧。緊急対応を入力待ちにしない。完了自動通知なし。治療/保険金完了とは別 |
| 決済/処分担当 | 実績異議、未払い、返金/チャージバック、取消免除、3/4/5件措置、退会・残予約・未精算・保全 | 運営の立替・売上預かり・制裁報酬没収なし。記録と人の必要な判断を残す |
| 運用担当 | 通知・料金/予約異常・公開事故・予算監視、障害対応、バックアップ復元、外部取引照合、費用/対応時間評価 | 受付時間・応答目標を未合意のまま約束しない。AI停止で通常予約や確定データ閲覧を止めない |

必要画面は公開検索/詳細、登録/認証、本人/児/訪問先、申請/再提出、チャット/一覧、お気に入り、見積り/依頼、予約一覧/詳細/カレンダー、延長/変更/取消、開始終了/引渡し/実績、異議/再支払い、売上/入金予定、レビュー/通報、お知らせ、権限別運営、規約/プライバシー/ヘルプ。画面の存在だけを受入にせずAPI・状態・保存・通知を接続する。

## 3. 全体で崩してはいけない条件
1. 年齢は利用日基準で生後6か月〜小学3年の年度末。訪問保育を基本とし、シッター宅預かりを受け付けない。保育士/看護師/幼稚園教諭と必要研修、資格別乳児条件、届出、初回保険を確認する。
2. 複数人は一律1人に狭めず上限3人。ただし地域基準・例外・年齢/関係・保険・担当者の全条件を確認した組合せだけ受付。未確認組合せは画面とサーバーで拒否する。
3. 病児/投薬は検索、依頼作成、承認、変更、投薬依頼の全経路で無効。通常予約への付替えも不可。利用中の体調変化は安全確保/保護者連絡の経路へ。Cの条件成立前に資料だけで開放しない。
4. 依頼承認期限は送信24時間後と開始の早い方。通常最低3時間/15分刻み、定期先4週・回別独立。承認/延長の競合と移動枠を原子的検査する。成立時の単価・規則・対象児・交通費等を履歴化し、改定を遡及しない。
5. 時給上限10,000円、人数倍率、夜間21〜8時20%、病児対象児30%（重なり50%）、中間非丸め/合計円未満切捨て。別日面談は人数倍率/病児加算なし30分単位、送迎は最低なし実績分単位。交通費/立替は事前同意・実費/証憑。保護者概算と正式総額を区別し、交通費未確定を0円にしない。
6. 運営手数料は対象保育/面談/送迎/延長/割増/取消料の15%、実費除外。シッター85%+実費、決済費は運営負担、外部から直接入金、運営立替なしの両立を契約検証する。独自カード処理・身分証代理回収なし。
7. 実績報告は終了24時間以内。保護者通知から24時間の未確認時に自動決済。異議中は停止、解決後の再提出は明示承認のみ。通知失敗で起算点を偽らない。署名検証/照合で成功を確定し、通知再送・連打で二重請求しない。
8. 未払いは全担当の新規依頼と承認待ち承認、成立済み予約開始を制限。ちょうど開始24時間前の未解消は50%取消、24時間前経過後の発生は対象未実施予約を即時100%取消。双方へWeb/メール通知。再支払い成功は残債全てを確認し制限解除するが取消予約は復活しない。実施中の安全な引渡しを妨げず二重取消料なし。
9. 通常の保護者取消は日本時間の暦日で前々日以前0/前日50/当日100%。シッター取消は請求なし、原則1件、証跡付き免除を記録。3/4/5件と暦月3か月リセットを維持。免除分は件数/起算日に影響させず、人の確認が必要な処分を自動確定しない。
10. ログインと本人性、公開/当事者/運営情報を分離する。保険確認状態/期限や原本は公開しない。非公開添付・期限付き閲覧・位置情報除去・サーバー権限・管理者MFA・入力/頻度制限・機微ログ禁止を全機能へ適用する。
11. 保存失敗・外部停止では成功を偽らず、直前の確定状態と入力を保持。再試行・再起動・同時操作を検証。予約状態と決済状態を分離し、異議と決済の競合は確定結果へ収束させる。
12. AIは根拠を限定した補助。予約/決済/医療/審査疑義/処分の自動確定権限を与えず、書類内命令を実行しない。不鮮明・偽装疑い・停止・予算超過を安全に人/定型処理へ戻す。

## 4. 公開を止めるゲート
- 全要件→タスク→受入証拠の対応と独立設計/計画レビューがあり、重要事項の担当・解決期限を特定する。重大な未決事項は「後で確認」で公開しない。
- 採用候補の認証・予約DBの原子性・添付保存・メール・決済の現行条件、制度/自治体/税/保険と取消条項の適合を担当が確認。Cloudflare/D1/R2、Clerk、Stripe Connectは候補であり契約済みとは扱わない。
- 実アクセス権限・決済の二重処理/異議/未払い・書類公開事故防止、通知停止/再試行、日次バックアップ・復旧/データ損失24時間以内の目標を実復元で確認する。目標が不達なら再設計し独立再評価。
- 同時20人/月300予約想定と主要画面3秒以内の測定、スマホ/デスクトップ・キーボード/ラベル/エラー/色依存の確認、PWA導線を実施する。オフラインで予約成功を偽表示しない。
- 小規模試験でシッター手取り、実質時給、定期利用率、空き枠成約率、支払遅延、運営の確認率/対応時間、1予約貢献利益、事故/誤判定/苦情を計測する。ソフト固定月5,000円+AI1,000円の上限目標、決済費別枠を実見積りと実測で確認。利益や無料枠継続を仮定しない。
- 利用規約/プライバシー/ヘルプと実装が一致し、事故受付責任・担当・対応目標・障害時連絡・復旧手順を運営が引き受けられる。公開対象版・環境の明示承認後にのみ公開する。

## 5. 残るユーザー判断は要件第29章の4群
| 判断群 | 担当が先に揃える具体案と判断期限 | ブロック対象 |
|---|---|---|
| D1 費用・契約・損失負担 | 最新見積り・契約方式・返金/チャージバック/負残高負担、合計6,000円以外の事業費。担当: 調査/設計→ユーザー。期限: 外部契約・決済接続前 | 契約/支出/本番決済。15%・直接入金・立替なしの再質問はしない |
| D2 安全上の提供範囲 | 地域/年齢/人数の適用表、最低保険補償、病児/投薬の薬/方法/同意/担当条件。担当: 制度/保険調査→ユーザー。期限: 当該提供の有効化前 | 未確認複数人組合せ、C提供。初期Rの通常保育等の適合確認も残る |
| D3 重大な制限・処分 | 長期異議/未承認精算の終了、追加制裁、定期一括取消の集計。担当: 例外設計→ユーザー。期限: 処分/精算仕様確定前 | 該当機能の確定と公開。金銭徴収撤回/3・4・5/3か月/全予約開始制限を維持 |
| D4 情報保存・運営責任 | データ別目的/起算/閲覧/削除/保全表、受付時間・担当・応答目標、運営保険。担当: 調査/運用設計→ユーザー。期限: 実情報取得・公開前 | 実情報保存/削除運用/公開。医療一律30日を採用しない |

通常UI・入力検査・同時処理・監視の設計、最新事実の調査をユーザーへの好みの質問へ置き換えない。4群は確認の整理で、質問数4件の約束ではない。

## 6. 現状の位置
現状はLの一部。最新の独立棚卸しを正本として読む。合成登録・本人プロフィール/児・料金/空き枠、通常単発検索→テキスト相談→見積り→依頼/承認/辞退等の証拠はあるが、全体の公開合格へ転用しない。現デモの3都県限定、固定30分移動枠、認証代替を製品の恒久仕様にしない。

初期公開からの対象外: ネイティブアプリ、アプリ内通話、SMS/プッシュ、位置追跡、シッター宅預かり、自動車運転/タクシー、独自本人確認/カード処理、運営の代替手配/立替。病児等は対象外ではなくCとして保持する。旧局所ロードマップは本書と全体チェックリストを入口に置き換え、過去の検証証拠として残す。
