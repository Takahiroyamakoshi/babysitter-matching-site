# UI/UX調査・改善監査
版: 0.2 / 確認日: 2026-10-17
対象: ローカル合成アプリの保護者による検索→相談→見積り。ユーザーのフィードバックを修正要件とする。設計・実装は UX-REFRESH.md を参照。

## 公開サイトの観察
公開画面をアプリ内ブラウザーで開き、現在の検索・絞り込み画面を保存して目視確認した。ログイン・会員登録・予約送信・網羅的なプロフィール収集は行っていない。
- [キッズライン公開検索](https://kidsline.me/sitter): PCは日付・開始終了をまとめた左列と結果の主領域。左列の「保育可能年齢」「保育人数」「時給」「資格」は独立見出し。1280px幅で左列見出しをDOM測定すると幅211px。主領域は画像上およそ680px、左右余白あり。スマホ390pxでは検索入口を上部へまとめ、結果を優先。日時選択と相手の絞り込みの意味を見出しで区別する点を採用する。
- [キズナシッター公開検索](https://sitter.kidsna.com/pref/all): 「ベビーシッターを探す」と目的を明示し、結果一覧に大きく幅を使う。絞り込みは別モーダルで、エリア・子どもの年齢・曜日時間帯・対応可能を分けている。今回の表示幅ではモーダルは約630px、一覧は3列。情報を開示する段階の分離を参考にする。
- 競合の写真・レビュー・プロフィール本文や見た目の複製はしない。掲載情報が多いことと、今回必要な入力が分かりやすいことは別。広い宣伝領域や横スクロールをそのまま採用しない。
- 公開範囲のみの観察。ログイン後のチャット・予約・確定見積りは確認していない。サイトごとの料金ルールや補助制度は本アプリへ流用しない。

## 現アプリの3ステップ監査
1. **検索・候補選択（改善必須）**：目的が曖昧なh1、対象児・日時・シッター条件の同居、4人の選択肢、無効な相談/見積りタブ、結果カードのスラッシュ区切りが判断を難しくする。保護者が入力する条件と、候補者が対応できる条件を独立した見出し・項目名で表示する。
2. **相談（改善必須）**：会話はできるが依頼日時・子ども条件の編集ができず、右側の多くが余白。会話を主領域、依頼条件を補助領域にし、会話と選択シッターを保持したまま編集できるようにする。
3. **概算・正式依頼（改善必須）**：保護者に運営手数料とシッター手取りが混在。交通費800円のfixtureが相談前から確定額として入り、総額7,400円と表示される。概算では保育基本額＋夜間加算＝交通費を含まない保育料概算を提示し、交通費は未確定と明示。正式依頼前に提案額と全支払総額を確認し、シッターが承認する。

## 検索バリデーションの実測
開始2026-10-24 10時、終了12時（日本時間）のAPI検索は200とsitters=[]を返した。入力不備と正しい条件での候補なしを区別できていない。修正はフロントの項目別エラーと、APIの入力検査を候補フィルタより先に行う。証拠: invalid-time-api.json。
ブラウザーのdatetime-localへのfillはblurで旧React値に戻る観測があり、07-before-invalid-time.pngは「3時間未満が候補ゼロ」の実測画面としては不採用。ユーザー報告、上記API実測、ソースの例外吸収を根拠に修正する。正常な候補ゼロは別の空状態として扱う。

## アクセシビリティ・画面配分
検索フォームはfieldset/legendや見出しで意味を区切り、全入力にラベル。エラーは該当欄とaria-describedby/aria-invalidで結び、送信時のエラー要約へフォーカスを移す。色だけで状態を伝えない。
PCでは入力と候補の優先順位を整理し、無内容の説明カードに約半分の幅を割かない。相談は会話をおよそ2/3、依頼条件を1/3とする設計目安。スマホでは一列、日時編集を会話の近くに置く。完全なアクセシビリティ適合は今回の画像観察だけでは判定しない。

後続: 全体サイドバー、全画面の固定リンク・URLルーティング、アカウント/子ども情報の本番管理。今回のユーザーが後続として述べた範囲を全面実装しない。

## 修正後の3ステップ確認
対象製品版: 46985e12b04024ac4761bff256580c0c702c7a20。親のCUA操作と画像確認、検証前後の版照合PASS。詳細は [検証記録](../verification/UX-REFRESH.md) と evidence/ux-refresh/S01/browser-checks.json。
1. **検索・候補選択（今回の指摘を解消）**：二つの独立カード、目的の明確なh1、1〜3人、児童別生年月日、項目/値の結果カード。相手未選択時は相談・概算タブなし。2時間は「通常保育は最低3時間です」と検索不可、有効な条件の0件は別の案内。
2. **相談（今回の指摘を解消）**：PCは会話と条件編集を左右に配置。日時を13:15から13:30へ変更しても相手と会話を保持。旧見積りと両確認チェックは失効し、再計算・再確認を要求する。
3. **概算・正式依頼（今回の指摘を解消）**：保護者は基本保育料・夜間加算・保育料合計を確認。交通費未確定時の総額は未確定。2児3.5時間の15,400円に提案交通費500円を加え15,900円で送信、シッターも明示確認して承認。運営手数料・手取りはシッター側だけに表示。
375pxでは一列になり、検索・相談・概算・承認の日本語と操作を画像確認。夜間19〜22時・2児は基本13,200円＋21〜22時の880円＝14,080円で二重加算なし。全体サイドバーは後続のまま。
