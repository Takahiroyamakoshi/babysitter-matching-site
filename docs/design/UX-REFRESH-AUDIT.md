## 実装・成果物レビューへの確認事項
下記は既存要件を具体化した確認点であり、設計差戻しや新しい業務要件ではない。
1. UX01: RequestConditions（対象児・日時）とSitterFilters（地域・資格・時給）は視覚的に独立したカード/領域と意味的なfieldset/legendで分ける。同じ混在カード内へ見出しだけ追加して完了としない。検索操作は両者をまとめてよい。
2. UX08: 基本額・夜間加算・保育料合計の表示値を照合し、夜間分を二重加算しない。既存の合計端数処理を変更しない。保護者向け取消説明も利用者に必要な取消条件を残し、不要な運営15%/シッター85%の説明を除く。シッター内訳は維持。
3. UX09/互換性: schema1 fixtureから旧pending依頼・成立予約・成功済みrequest操作・成功済みapprove操作を読み込み、再起動後も保存額を維持する。旧成功request/approveを元の入力/operationIdで再送して同一結果となること、新規操作では確認必須であること、異内容の再送が既存契約に従い拒否されることを確認する。新フィールドを古いfingerprintへ無条件追加して過去成功を409/422にしない。旧pending承認でも保存料金を現在fixture額へ置換しない。
4. UX07/09: 子どものDOB・日時・相手・交通費変更と再見積りで同意を失効させる。遅れて返る見積りが新条件へ適用されないこと、空の交通費入力が数値変換で0にならないことを確認する。
